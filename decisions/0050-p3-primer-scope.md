# 0050 — Phase 3 primer scope, structure, and budget

**Status:** Accepted
**Date:** 2026-04-28
**Phase:** 3, Stage 1
**Closes:** [phase-3-plan.md Q-P3-4](../plans/phase-3-plan.md)

## Context

[tacit-plan.md § Phase 3](../plans/tacit-plan.md) sizes the primer at
"10–17K tokens." [phase-3-plan.md § Stage 7](../plans/phase-3-plan.md)
requires the primer to teach Tacit-Lite to a model "from a primer
alone" well enough to clear the Phase 3 gate (Sonnet > 70% pass on
the open + sealed corpus, ≥ 30% token reduction vs Python).

A 10–17K token window is wide enough for two materially different
primer designs:

- **Compact (~10K).** Tight semantic summary, ~10 worked examples,
  catalogs that lean on the model's prior fluency to bridge gaps.
  Cheaper per eval run; depends on the model under test
  generalising aggressively from few examples.
- **Expansive (~17K).** Long semantic summary, 20+ examples,
  exhaustive idiom and error catalogs that minimise generalisation
  burden. More expensive per eval run; degrades the 30% token
  reduction gate (the primer counts as input tokens per
  [ADR 0021](0021-corpus-stdlib-dominance-reporting.md)).

The user's preference per the Stage 1 design pass is the **compact**
end of the window. The reasoning is direct: Phase 3's gate is a
*primer-only* falsification test. If the language genuinely
generalises from a small primer, the compact primer demonstrates that
property; if the language only works with a sprawling primer, the
parent plan's Phase 5 path (synthetic corpus + fine-tuning) becomes
the relevant track.

The Q-P3-4 deferral also asks for the section list, per-section
length budget, fluency target, and filename / location. The parent
plan already pins the section list to six categories; this ADR
budgets each one.

## Decision

**The primer targets ~10,500 tokens under tiktoken `o200k_base`
([ADR 0001](0001-target-tokenizer.md)), with a hard cap of 12,000
tokens. Six sections in fixed order, each with a budget. Authoring-
view fluency is gated against Sonnet at > 70% pass per the parent
plan; Haiku fluency is reported but not gated.**

### Filename and location

- **Path:** `plans/primer/tacit-lite-primer.md`.
- The `plans/primer/` directory is new and contains only the primer
  and any primer-fixture support files (e.g., a per-section index
  generated by the Stage 7 primer fixture).
- The primer is markdown with fenced code blocks. Tacit-Lite snippets
  are fenced as ` ```tacit ` — a fence tag chosen so the Stage 7
  extractor recognises them unambiguously.
- The primer is checked into the repo and tracked by `git`. Diffs to
  the primer are PR-reviewed under the same discipline as ADR text.

### Section list and budgets

Sections are written in fixed order; the model reads them
sequentially. Budgets are upper bounds; a section may come in under
budget. The total budget sums to 10,500 tokens; the buffer between
total and cap (12,000) absorbs unforeseen overrun in any one section.

| Section                              | Budget (tokens) | Source authority                                   |
|--------------------------------------|-----------------|----------------------------------------------------|
| 1. Semantic summary                  | 700             | This ADR + ADRs 0034–0046 in summary form.         |
| 2. Progressive Python/Rust ↔ Tacit pairs | 3,500       | `examples/smoke/`, `examples/phase-3/`, fresh prose|
| 3. Idiom catalog                     | 1,800           | [ADR 0048](0048-p3-tacit-idiom-rules.md)           |
| 4. Effect-reasoning examples         | 1,800           | ADRs 0035, 0036, 0046; `examples/phase-3/`         |
| 5. Negative examples + diagnostics   | 1,500           | [ADR 0041](0041-p2-structured-error-format.md)     |
| 6. Compiler error catalog            | 1,200           | ADR 0041 diag-id surface                           |
| **Total target**                     | **10,500**      |                                                    |
| **Hard cap**                         | **12,000**      |                                                    |

### Section content rules

**Section 1 — Semantic summary.** One page (~700 tokens). Names the
big-picture facts: closed-lambda discipline, content-addressed AST
with display-name sidecar, four-atom effect lattice, primitive
surface via `@name`, no implicit mutable state. No code blocks.
Explicit cross-references to the section that demonstrates each
fact.

**Section 2 — Progressive examples.** Twelve worked Python/Rust ↔
Tacit-Lite pairs, ordered shortest-to-longest. Each pair is one
problem, three side-by-side snippets (Python, Rust, Tacit-Lite),
and 1–3 sentences naming what changed. Source rule per
[ADR 0049 § Primer source rule](0049-p3-examples-layout-contamination.md):
snippets come from `examples/smoke/`, `examples/phase-3/`, or fresh
prose — never from `corpus/tasks/<...>/reference.tac`. Example
selection covers: arithmetic primitive use, recursion via `rec`,
`match` over `i64`, closures and `let`, byte buffer use,
`@parse-i64` / `@fmt-i64` round-trip, file I/O via stdin slurp.

**Section 3 — Idiom catalog.** Pinned canonical forms from
[ADR 0048](0048-p3-tacit-idiom-rules.md): lambda forms, `rec`
shape, `match` shape, `let` shape, primitive call sites, exported-
binding annotation shape. Each idiom is one short paragraph plus
one example. Negative idioms (what *not* to write) are out of scope
for this section — they live in section 5.

**Section 4 — Effect-reasoning examples.** Six worked examples
showing how effects propagate: a pure function and its `{}`
annotation, a `{Mut}` function operating on a `Buf`, an `{IO}`
function calling `@read`/`@write`, a function whose effects are
`{Alloc, Mut}` calling `@buf-alloc-dyn` then `@fmt-i64`, an
effect-polymorphic higher-order function (one example only,
reusing the smoke-corpus pattern), and an example of effect
**purity violation** caught by the typechecker. Each example is
~250–300 tokens.

**Section 5 — Negative examples and diagnostics.** Ten short
programs that fail to compile, paired with the exact JSON
diagnostic the compiler emits per
[ADR 0041](0041-p2-structured-error-format.md), and the fix.
Categories: type mismatch, effect mismatch, scope error, primitive
arity error, unknown primitive, missing module annotation, two
typed-program errors specific to Phase 2. Each entry: failing
program (~30 tokens), diagnostic JSON (~50 tokens), one-sentence
fix (~20 tokens), corrected program (~30 tokens) — ~130 tokens
per entry × 10 entries = 1,300 tokens, with the remaining 200
tokens for the section header.

**Section 6 — Compiler error catalog.** A flat list of the diag-ids
from [ADR 0041](0041-p2-structured-error-format.md): one line per
diag-id, ~50 tokens of "this is when it fires, here is the typical
fix pattern." The Stage 7 author lists every diag-id the Phase 2
typechecker can emit; the per-line budget keeps the section under
1,200 tokens for the full set.

### Fluency target

- **Primary gate:** Sonnet (`claude-sonnet-4-6` per
  [ADR 0052](0052-p3-eval-model-contract.md)) achieves > 70% pass on
  the open + sealed corpus from this primer alone, per the parent
  plan's Phase 3 exit criterion 1. This is the load-bearing target.
- **Reported but not gating:** Haiku (`claude-haiku-4-5`) pass rate
  on the same corpus from the same primer. Haiku is expected to
  underperform Sonnet by 10–25 percentage points on a primer-only
  task; the report is a data point on primer compactness, not a
  pass/fail signal. If Haiku exceeds 70%, that is documented as
  evidence that a smaller primer or a smaller model could clear
  the gate; if Haiku falls below 50%, that is documented as
  evidence that the primer is right-sized for Sonnet but not
  smaller models.

### Compactness discipline

- **Hard cap is binding.** Stage 7 must not ship a primer over
  12,000 tokens. If the budget cannot be met, the failure mode is
  to drop section content — preferentially in section 2 (drop a
  pair) or section 5 (drop an entry) — never to inflate the cap.
  Per [phase-3-plan.md § Risks](../plans/phase-3-plan.md), an
  uncapped primer is a Phase 5 signal, not a Phase 3 primer-design
  knob.
- **Section budgets are soft until the total nears the cap.** A
  section that needs 200 extra tokens can borrow from another
  section's slack, provided the total stays under 12,000 and the
  section stays within ±20% of its budget.
- **No filler.** Every paragraph either teaches a concept the model
  cannot derive or pins an idiom the harness will measure. Prose
  that paraphrases the language reference for stylistic variety is
  rejected at PR review.

### Authoring discipline

- **Single-author cohesion.** The primer is a teaching artifact;
  inconsistency in voice or vocabulary across sections measurably
  hurts model performance. Stage 7 sessions A and B per
  [phase-3-plan.md § Stage 7](../plans/phase-3-plan.md) are written
  by the same author; if a second author edits, the edit is a
  consistency pass, not new section content.
- **Snippets compile.** Every fenced ` ```tacit ` block in the
  primer must compile and typecheck under the Stage 7 primer-fixture
  test. Snippets that demonstrate a *failure* (section 5) are
  marked with a fence-attribute `tacit{fail=diag-id}` or similar
  so the fixture knows the expected failure mode.
- **No display-name renames for token budgeting.** Same rule as
  [ADR 0048 § Authoring view](0048-p3-tacit-idiom-rules.md): names
  reflect what an author would type, not what minimises tokens.

## Alternatives considered

- **Target the upper end (~17K).** Rejected. The wider primer
  reduces the 30% token-reduction gate's headroom (every primer
  token is a Tacit-Lite token in the eval's input column), and the
  parent plan's Phase 5 path is the deliberate remedy if the
  compact primer fails. Inflating the primer is a tempting but
  lossy compensation.
- **Target a middle value (~13K).** Rejected as not-decisive. A
  middle target without a written rationale is a stalling tactic.
  10K commits to the "language generalises from a small primer"
  thesis; if that thesis fails the response is Phase 5, not 13K.
- **Multiple primer variants** (compact for Sonnet, expansive for
  Haiku, etc.). Rejected for Phase 3. Cross-family / per-model
  primer variants are the Q-P3-8 question per
  [ADR 0054](0054-p3-cross-family.md); within Q-P3-4 a single
  primer is the cheapest path. If the data justifies a Sonnet vs
  Haiku split later, that becomes a follow-up ADR.
- **Drop the compiler error catalog (section 6) and rely on
  in-context diagnostics.** Rejected. The catalog is the cheapest
  way to teach diag-ids to a model that has never seen them; 1,200
  tokens for the full Phase 2 surface is a strong return on a
  small budget.
- **Move the negative examples (section 5) to a separate primer
  used only on edit/repair tasks.** Rejected. The maintenance
  sub-track per [ADR 0053](0053-p3-maintenance-subtrack.md) uses
  the same primer; a separate maintenance primer doubles the
  authoring cost and the eval-time token count without
  demonstrably improving repair performance.
- **Place the primer at the repo root** (`PRIMER.md`). Rejected.
  `plans/` is where in-repo design artifacts live; `plans/primer/`
  keeps the primer adjacent to the plan that defines it and the
  ADR that scopes it.

## Consequences

- **Stage 7 has a concrete brief.** The author knows exactly which
  six sections to write, with budgets per section and a hard cap.
  Session A (sections 1–3) and Session B (sections 4–6) are
  natural cuts.
- **The 30% reduction gate has known input cost.** The primer is
  ~10,500 tokens; per-task generation is the model's output. The
  Phase 3 token-cost report (per
  [ADR 0055](0055-p3-metrics-schema.md)) has a clean primer-input
  column.
- **Compactness becomes a Phase 3 thesis check.** If the compact
  primer fails the gate, the parent plan's Phase 5 path is
  triggered with clean data; if it passes, the language's
  generalisation thesis is supported by the smallest-possible
  primer.
- **Primer-fixture tests run on every push.** Every snippet
  compiles; every snippet's diag-id is what the catalog claims;
  every contiguous 32-token run is checked against
  `corpus/tasks/<...>/reference.tac` per
  [ADR 0049 § Mechanical enforcement](0049-p3-examples-layout-contamination.md).
- **The primer freezes at Stage 7 exit gate.** Changes after Stage
  9 require a freeze-revision ADR. Pre-freeze edits in the
  primer-revision cycle (per
  [phase-3-plan.md § Stage 11](../plans/phase-3-plan.md)) are
  expected; post-freeze edits are spec amendments.
